# TopOut

> 등반 시작부터 완등 순간까지, 자동으로 찾아주는 클라이밍 촬영 앱

TopOut은 실내 클라이머를 위한 스마트 등반 영상 녹화 앱입니다.

TopOut이 사용자의 움직임을 분석해 등반 시작부터 완등 순간까지 필요한 구간을 자동으로 찾아줍니다. 한 번의 영상에 여러 번의 등반이 담겨 있어도 각각의 시도를 구분합니다.

촬영이 끝나면 자동으로 선택된 구간을 확인하고, 시작점과 종료점을 원하는 위치로 세밀하게 조정한 뒤 필요한 장면만 사진 앱 또는 갤러리에 저장할 수 있습니다.

**출시 상태: iOS · Android 모두 출시 완료**

[App Store에서 TopOut 보기](https://apps.apple.com/kr/app/topout/id6790163178) · [Google Play에서 TopOut 보기](https://play.google.com/store/apps/details?id=com.topout.cam)

## 주요 기능

- 매트 경계 자동 탐지 및 직접 보정
- 움직임을 분석해 등반 시작과 종료 시점 감지
- 한 번의 촬영에서 여러 등반 시도 자동 구분
- 자동으로 찾은 구간을 간편하게 미세 조정
- 원하는 등반 장면만 사진 앱 또는 갤러리에 저장
- 촬영 중단과 저장공간 부족 상황에 안전하게 대응
- 기기 언어 자동 선택과 앱 내 수동 언어 변경 지원

모든 영상 분석은 사용자의 기기 안에서 이루어집니다. 긴 영상을 다시 돌려보며 등반 장면을 찾고 편집하는 시간을 줄이고, 클라이밍에 더 집중할 수 있도록 설계했습니다.

앱 UI는 영어, 한국어, 일본어, 중국어 간체, 중국어 번체, 프랑스어, 독일어, 스페인어, 포르투갈어를 지원합니다. 기본값인 `자동`은 운영체제 언어 우선순위를 따르며, 설정에서 원하는 언어를 고르면 저장 전에도 설정 화면이 즉시 해당 언어로 바뀍니다. 지원하지 않는 기기 언어는 영어로 표시합니다. 긴 번역은 버튼 내에서 두 줄 가운데 정렬과 자동 크기 조정을 사용해 버튼 밖으로 나가거나 말줄임표로 숨지 않게 구성합니다.

Android 버튼은 기존 화면 배치를 유지하면서 내부 여백과 아이콘 간격을 줄이고 자동 축소의 최소 글자 크기를 높여, 프랑스어·독일어처럼 긴 문구도 두 줄 안에서 전체 내용을 읽을 수 있게 합니다.

모든 영상 프레임, 관절 좌표, 중간 분석 결과는 기기 안에서 처리하며 외부 분석 서버로 전송하지 않습니다.

양 플랫폼 촬영 화면의 하단 Tip 배너는 가로폭 기반 글자 크기 조정을 사용해 좌우 여백을 유지하며 한 줄로 표시합니다. 9개 언어 모두 `파란 점으로 경계선 보정`, `분석 뒤 벽과 매트 경계 보정`처럼 대상과 행동을 함께 안내하고, 화면 폭에 맞춰 자동 축소합니다.

양 플랫폼의 촬영·선택·결과 화면 상단 문구는 한 줄로 고정하고 화면 폭에 맞춰 자동 축소합니다. 번역을 지나치게 줄이지 않고 `벽과 매트 사이의 경계`, `녹화 시작`, `감지된 시작~완등 구간`처럼 사용자가 확인하거나 조작할 대상을 9개 언어에서 명확히 표시합니다. iOS는 Dynamic Island 아래 안전 영역에 한 줄 높이로 배치하며, 가로모드 결과 컨트롤도 노치 안전 영역 안에 둡니다.

## 제품 흐름

```text
모델·카메라 준비
→ 촬영 포맷과 구도 설정
→ 준비 완료 이후 안정된 새 프레임으로 매트 경계 분석
→ 라이브 프리뷰에서 매트 보정·선택적 탑홀드 지정
→ 녹화 시작 또는 준비 완료 상태 1분 후 자동 시작
→ 3초 카운트다운 후 연속 녹화
→ Motion / Pose 기반 다중 등반 구간 탐지
→ 구간 검토·정밀 편집·재촬영
→ 시스템 갤러리 저장 후 실제 저장 항목 재조회·재생 검증
```

자동 탐지는 편집 후보를 제안합니다. 원본 녹화는 자동 구간이 끝나도 중단되지 않으며 사용자가 종료할 때까지 계속됩니다.

### 앱 소스 책임 구분

- Android는 `TopOutViewModel`이 화면 상태를 조정하고, `camera/`, `detection/`, `sam/`, `media/`가 카메라·탐지·분할·저장을 각각 담당합니다. Compose 화면은 `ui/screens/`의 흐름 파일과 조작부·오버레이·보조 화면 파일로 나눴습니다. `CameraEngine`의 후면 렌즈 탐색·기능 조회·화면비 계산은 `camera/`의 별도 파일로 분리했습니다.

- 플랫폼별 세부 파일 역할과 수정 시작점은 각 README의 `코드 구조` 절을 기준으로 합니다.

## 개발 흐름과 의사결정

TopOut은 iOS 카메라·MobileSAM 프로토타입에서 시작해 Motion 기반 연속 촬영, Vision Pose, 결과 편집을 차례로 연결한 뒤 Android로 제품 흐름을 확장했습니다. Android에서는 ML Kit, MediaPipe, EfficientDet, YOLO11 Pose, PP-TinyPose와 MoveNet Lightning을 비교했고, 정확도·장시간 전력·앱 크기·라이선스·배포성을 함께 평가해 MoveNet Thunder FP16과 LiteRT로 정착했습니다.

현재 구조는 한 번에 결정된 결과가 아닙니다.

```text

→ 암장별 조명·그림자·볼륨 예외 확인
→ MobileSAM 후보 분할 + 구조 필터 + 수동 보정
```

## 촬영 준비와 프레임 정합성

선택 UI에는 캡처된 정지 이미지를 표시하지 않습니다. 매트 보정과 탑홀드 선택은 계속 움직이는 실제 카메라 프리뷰 위에서 진행하고, MobileSAM 입력 프레임만 내부에서 별도로 캡처합니다.

### iOS

- 앱 진입과 카메라 프리뷰 준비는 MobileSAM 로딩을 기다리지 않으며, 실제 프리뷰가 안정된 뒤 CPU·Neural Engine으로 모델을 백그라운드에서 준비합니다.
- 시작 화면은 고정 시간 없이 표시하고, 카메라 세션 구성이 끝나거나 권한 거부·카메라 오류가 확인되면 닫습니다.
- AVAudioSession 구성·활성화는 전용 직렬 큐에서 처리해 주 스레드 hang 위험을 없애고, 녹화·마이크 해제·결과 재생 전환의 순서를 유지합니다.
- 실제 비디오 프레임 6장이 도착하기 전에는 `준비 완료`를 활성화하지 않습니다.
- Ready 이후 최소 4개의 새 프레임과 0.2초를 기다리고, 노출·초점·화이트밸런스가 2프레임 연속 안정된 프레임을 우선 사용합니다.
- 3A가 계속 조정 중이면 0.9초 후 최신 프레임으로 진행하며 전체 요청 제한은 1.8초입니다.
- 선택한 촬영 포맷이 이미 적용된 경우 Ready에서 불필요하게 재설정하지 않습니다.

### Android

- 앱 진입과 카메라 프리뷰 준비는 MobileSAM ONNX 세션 로딩을 기다리지 않으며, CameraX 프리뷰가 안정된 뒤 모델을 백그라운드에서 준비합니다.
- CameraX Preview가 실제 `STREAMING` 상태이고 선택한 줌이 적용된 뒤 `준비 완료`를 활성화합니다.
- 시작 화면은 iOS와 같이 고정 시간 없이 권한 요청 동안 유지하고, 카메라 연결 성공·실패 또는 권한 거부가 확인되면 닫습니다.
- Ready 이후 새 ImageAnalysis 프레임 6장을 건너뛴 프레임을 자동 매트 분석에 사용합니다.
- Preview, VideoCapture, ImageAnalysis는 같은 ViewPort와 화면비 좌표계를 공유합니다.
- Android 16 대화면에서 orientation 요청이 무시되는 경우에도 Ready 시점 회전·구도를 세션 동안 고정합니다.

#### 멀티 렌즈 줌

- 논리 멀티 카메라가 지원하는 렌즈 구간은 CameraX의 연속 줌으로 통과하고, `0.5x·1x 논리 카메라 + 별도 망원` 혼합형에서는 논리 그룹 밖의 망원 경로를 추가로 유지합니다.
- 물리 카메라 재바인딩이 필요한 확대 전환은 현재 프리뷰 정지 프레임을 핀치 배율에 맞춰 움직이다가 손을 뗄 때 최종 배율로 실행합니다. 이전 렌즈 경계까지 되돌아오면 예약을 취소하고 기존 라이브 카메라로 즉시 복귀합니다.
- 축소는 즉시 렌즈를 전환하고, 새 프리뷰의 스트리밍과 목표 줌 적용이 확인된 뒤 정지 프레임을 페이드합니다. 전환 실패 시 이전 렌즈 복구를 시도합니다.

두 플랫폼 모두 Ready 이후 렌즈·줌·회전을 고정하며, 탑홀드는 탭할 때마다 새 프레임과 새 임베딩으로 계산합니다.

자동 구간 탐지를 사용하면 매트 경계 분석이 끝난 시점부터 1분 동안 `녹화 시작`을 누르지 않았을 때 현재 경계를 기준으로 기존 3초 카운트다운을 시작합니다. 탑홀드 마스킹을 사용하면 탑홀드 선택까지 완료된 시점부터 1분을 계산하며, 탑홀드를 다시 선택하면 대기 시간도 새로 시작합니다. 대기 중에는 기존 선택 안내를 유지하고 자동 시작 5초 전에만 곧 자동 녹화를 시작한다는 문구를 잠시 표시합니다. 재촬영하거나 앱이 백그라운드로 이동하면 예약을 취소하고, 선택 화면으로 돌아온 뒤 다시 1분을 기다립니다.

## MobileSAM 매트 경계

두 플랫폼은 같은 자동 후보 규칙을 사용합니다.

- Positive X: `50%`
- Positive Y: `70%`, `80%`, `90%`, `95%`
- Negative point: `x = 50%`, `y = 28%`
- 상단 직선 지지 비율: 선택 영상 너비 `60%` 이상. 서로 떨어진 마스크 조각도 이상치에 강한 동일 직선 위에 있으면 합산하며, 빈 열과 위·아래로 튀는 열은 제외
- 마스크 최상단: 선택 영상 높이 `50%` 이하 영역에서 시작
- 상단 경계 기울기: 최대 `15°`
- 유효 후보 중 화면에서 가장 높은 상단 경계 선택
- 경계를 `x = 6%`, `x = 94%`의 편집 가능한 두 점으로 변환
- 후보가 없으면 선택 영상의 `y = 75%` 수평 기본선 사용
- Core ML 또는 ONNX Runtime 분석이 5초 안에 끝나지 않으면 로딩을 종료하고 `y = 75%` 기본선을 표시하며, 늦게 도착한 결과는 현재 선택 화면에 반영하지 않음
- 탑홀드 분석은 매트 분석과 별도로 5초를 제한하며, 시간 초과·모델 오류·빈 결과에는 탭 위치의 기본 원형 마스크로 선택을 완료하고 늦게 도착한 결과는 반영하지 않음
- 별도의 10px 하향 보정 없음

기울어진 매트는 평균 Y 하나로 축약하지 않고 관절의 x 위치마다 직선을 보간해 시작선·종료선을 계산합니다.

## Motion과 Pose 상태 정책

공통 Motion 기준:

- 분석 프레임 너비 `160px`
- 현재 분석 프레임과 직전 분석 프레임 비교
- 기본 주기 `2fps`, 시작 전·종료 후·유실 복구 `4fps`
- 픽셀 밝기 차이 기준 `20`
- 매트선 위 선택 영상 높이 최대 `40%`에서 초기 탐색
- 노이즈 보정 `2.5%`, 보정 후 활성 기준 `2%`
- 활성 등반 중 Pose 유실 허용 `6초`
- 정상 종료 후 Pose 2회 연속 미검출 시 초기 Motion 탐색 복귀

30fps·60fps 선택은 촬영·인코딩 프레임률이고 분석 주기와 분리됩니다. iOS는 `CMSampleBuffer`의 presentation timestamp, Android는 `ImageProxy`의 센서 timestamp를 기준으로 0.5초·0.25초 간격을 제한하므로 두 설정 모두 상태별 분석 상한은 2fps·4fps입니다. 분석이 기기 성능보다 오래 걸리면 양쪽 모두 최신 프레임만 유지해 큐 적체를 막으므로 실제 빈도는 상한보다 낮아질 수 있습니다.

| 판정 | iOS | Android |
|---|---|---|
| 시작선 | x별 매트선보다 선택 영상 높이 6% 위 | x별 매트선보다 선택 영상 높이 6% 위 |
| 종료선 | x별 매트선보다 선택 영상 높이 4% 위 | x별 매트선보다 선택 영상 높이 4% 위 |
| Pose 입력 | active crop, 긴 변 최대 384px | Motion/Pose ROI, 256×256 RGB |
| 사람 검증 | Motion 격자와 직전 추적 대상에 가장 잘 이어지는 Vision observation 1명 | SinglePose의 4개 신체 그룹 중 3개 이상 |

Android의 4개 그룹은 어깨·골반·팔꿈치·무릎이며, 각 그룹은 좌우 중 하나가 confidence `0.25` 이상이면 충족합니다. iOS는 8열 저해상도 Motion 격자의 변화 영역과 겹치고 가까운 사람을 최초 대상으로 선택합니다. 이후에는 직전 선택 인물의 관절 경계와 중심에 가장 자연스럽게 이어지는 Vision observation 한 명만 시작·종료·완등 판단에 사용하며, 중심 거리 상한으로 후보를 제외하지 않습니다. 포즈가 실제로 검출되지 않을 때는 기존 Pose 유실 정책을 거쳐 초기 Motion 탐색으로 복귀합니다.

Android는 최초 MoveNet ROI를 선택된 움직임 영역의 긴 변 `1.5배`, 추적 ROI를 confidence `0.15` 이상 관절 영역의 긴 변 `1.5배`인 정사각형으로 구성합니다. 영상 가장자리에서는 정사각형 크기를 유지하기 위해 필요한 축만 검은 패딩을 사용하며, ROI가 영상의 긴 변보다 커지는 경우에만 전체 영상 크기로 제한합니다.

두 플랫폼 모두 신뢰 가능한 어깨와 골반이 각각 `1개` 이상 확인되어 어깨-골반 축이 성립하고, 확인된 몸통 관절이 선택 영상 중앙 `80%` 안에 있을 때만 기존 시작 판정을 그대로 사용합니다. 어깨나 골반 그룹 중 하나라도 보이지 않거나 몸통 관절 하나라도 좌우 `10%` 가장자리에 있으면, confidence 기준을 통과한 무릎·발목이 합계 `3개` 이상이면서 그중 발목이 `1개` 이상일 때만 새 등반의 시작 후보로 사용합니다. 팔·다리 일부만 가장자리에 닿는 경우에는 이 보정을 적용하지 않습니다. 화면 밖으로 이동해 몸통·하체가 잘린 사람의 남은 관절만 매트 시작선 위에 잡히는 경우를 제외하기 위한 조건이며, 이미 시작된 등반의 추적·종료 판정에는 적용하지 않습니다.

시작·종료·최고점·탑홀드 판단에는 어깨, 팔꿈치, 손목, 골반, 무릎, 발목을 사용하며 얼굴 관절은 제외합니다.

## 감지 구간과 리뷰

1. 패딩 없는 원본 구간을 시작 시각 순으로 정렬합니다.
2. 원본 길이가 2초 미만인 구간만 확인합니다.
3. 앞뒤 이웃 중 원본 간격이 3초 이내인 가장 가까운 구간과 병합합니다.
4. 병합할 이웃이 없는 짧은 구간은 제외합니다.
5. 나머지 정상 구간은 다음 시도와 가까워도 각각 유지합니다.
6. 각 구간에 iOS는 앞뒤 3초, Android는 시작 전 5초·종료 후 3초 편집 여백을 적용하며 원본 영상 범위 안으로 제한합니다.
7. 녹화 전체 길이 안으로 범위를 제한합니다.

결과 화면은 전체·최대 30배 확대 타임라인, 0.1초 미세 조정, 구간별 저장 상태, 중복 범위 방지, 촬영 컨텍스트를 유지한 재촬영을 제공합니다. 선택 구간 확대 배율은 작은 손잡이를 정확히 잡지 않아도 슬라이더 트랙을 탭하거나 진동 없이 바로 드래그해 조절할 수 있습니다. 다시 촬영 확인창은 긴 경고 본문만 작게 표시해 확인·취소 버튼과 정보의 위계를 분리합니다. 시작점을 수정하고 손을 떼면 새 시작점부터, 끝점을 수정하면 새 끝점의 3초 전부터 자동 재생해 편집 결과를 바로 확인합니다.

iOS는 선택 구간 시작점이 H.264 키프레임 사이에 있어도 저장 영상 첫 화면이 멈추지 않도록 마스크 포함 여부와 관계없이 고화질 재인코딩합니다. Android는 Media3 Transformer로 비키프레임 시작 구간을 재인코딩하고 결과 파일이 첫 영상 프레임부터 시작하도록 타임스탬프를 정렬합니다.

## 갤러리 저장 검증

내보내기 성공만으로 저장 완료를 표시하지 않습니다. 사용자가 실제로 접근할 시스템 갤러리 항목을 다시 열 수 있어야 저장 성공으로 확정합니다.

### iOS

```text
PhotoKit 저장
→ 생성된 localIdentifier 보관
→ 동일 PHAsset 재조회
→ 실제 AVAsset 요청
→ 사진 보관함 asset 재생
```

### Android

```text
MediaStore 게시
→ 동일 content URI 재조회
→ 파일 디스크립터·입력 스트림·메타데이터 확인
→ 동일 content URI를 Media3로 재생
```

Android 저장 영상 보기에는 앞/뒤 5초 이동, 드래그 즉시 화면이 따라오는 슬라이더, 영상 가림을 줄인 반투명 컨트롤이 적용돼 있습니다. 두 플랫폼 모두 여러 클립의 저장·검증 식별자를 구간별로 유지합니다.

## 카메라와 저장 안정성

- 기본값: FHD, 60fps, 9:16, 자동 구간 탐지 ON, 탑홀드 마스킹 OFF, 녹화 중 프리뷰 OFF
- 지원 후보: FHD / 4K, 30 / 60fps, 9:16 / 4:5 / 3:4 / 1:1, 세로 / 가로
- 지원하지 않는 조합은 기기에서 보장되는 포맷으로 폴백
- Android 60fps는 Preview·VideoCapture·ImageAnalysis의 활성 세션 전체가 정확한 FPS를 보장할 때만 선택
- 백그라운드 전환, 카메라·마이크 중단, 세션 오류, 저장공간 부족 시 원본을 먼저 안전하게 종료
- Android는 선택·녹화·저장 중 시스템 뒤로가기가 진행 중인 분석·녹화·내보내기를 중단하지 않도록 상태별로 처리
- 결과 화면에서는 시스템 자동 잠금 시간을 따르며, 결과 및 갤러리 저장본 플레이어는 앱이 백그라운드로 이동하면 일시정지
- iOS는 오디오 인터럽션 종료 후 마이크 캡처 그래프를 복구하고 세로 UI를 하단 안전 영역 안에 유지
- 최소 저장공간: `max(1GB, 예상 2분 영상 용량 + 256MB)`
- 저장공간은 녹화 시작 전과 녹화 중 1분 간격으로 확인
- 앱이 강제 종료되거나 OS가 프로세스를 정리해 남은 원본·내보내기 임시 영상은 다음 실행 시 백그라운드에서 삭제

### 저사양·장시간 촬영 자원 관리

- iOS 사진 저장은 `PhotoLibraryVideoSaver`, 저장 검증·재생용 조회는 `PhotoVideoRequest`가 담당합니다. 조회는 전체 20초 안에서 최대 3회 시도하며 완료·실패·timeout을 한 번만 전달합니다. 사진 보관함 쓰기가 끝나기 전에는 입력 파일을 유지합니다.
- 양 플랫폼은 모델 로딩·전처리·인코더 반환 이후에도 취소를 확인합니다. iOS 선택 분석은 백그라운드 진입에서 무효화하고, Android 전처리 예외는 해당 프레임을 해제한 뒤 다음 프레임에서 복구합니다.

- iOS MobileSAM 분석은 요청마다 픽셀 맵·임베딩·좌표 배율을 소유하고 timeout이나 화면 전환 시 취소 토큰을 전달해, 이전 요청의 결과와 큰 중간 버퍼가 다음 선택에 섞이지 않게 합니다.
- iOS 녹화기는 4K·60fps 입력이 writer 처리 속도보다 빨라도 전체 해상도 프레임이 메모리에 계속 쌓이지 않도록 캡처 큐에 역압력을 적용합니다.
- iOS는 실제 녹화가 시작될 때만 recorder·Motion 입력을 열고, 녹화 종료 시 진행 중인 분석 뒤 열린 구간을 비동기로 회수합니다. 카운트다운 취소나 앱 전환 뒤 도착한 이전 카메라 요청은 세대 번호로 폐기합니다.
- iOS 내보내기 작업과 파생 파일은 recorder가 소유하며 재촬영·닫기에서 취소·삭제합니다. 결과 재생은 저장 시작 전에 멈추고, 백그라운드나 화면 종료 시 PhotoKit 저장본 조회를 취소합니다.
- Android MobileSAM은 네 프롬프트를 순차 평가하고 ONNX direct buffer와 고정 zero-mask 입력을 재사용해 분석 순간의 중간 메모리와 복사를 줄입니다.
- Android는 MobileSAM 임베딩 해제와 세션 종료를 진행 중인 ONNX 호출과 직렬화하고, timeout 이후 보정 반복 사이에서 coroutine 취소를 확인해 추가 decoder 호출을 중단합니다.
- Android Motion/Pose 분석은 2fps·4fps 주기를 유지하면서 두 개의 luma 버퍼를 순환해 장시간 촬영 중 할당·GC 부하를 줄입니다.
- Android는 모든 CameraX 분석 경로에서 `ImageProxy`를 한 곳에서 해제하고, 화면 종료 시 분석 executor를 비운 뒤 네이티브 pose detector를 닫습니다.
- Android는 영상 메타데이터 읽기와 MediaStore 복사·검증을 IO dispatcher에서 수행하고, 원본·내보내기 파일과 pending MediaStore 항목의 소유·실패 정리를 명시합니다.
- Android는 Motion 셀 점수와 전체 변화율을 한 번에 계산하고, 중지 전 추론과 녹화 시작 콜백이 다음 촬영 상태를 바꾸지 못하도록 분석·녹화 요청 세대를 검증합니다. 결과 재생은 저장 시작 전에 멈춥니다.
- 두 플랫폼 모두 분석 결과·타이머·카메라·플레이어 수명을 화면 상태에 맞춰 정리합니다. 시뮬레이터와 빌드 검증은 실제 저사양 기기의 peak RSS·프레임 드롭·발열을 대신하지 않으므로 릴리스 전 실기기 점검이 필요합니다.

## 빌드

### iOS

1. `iOS/TopOut/TopOut.xcodeproj`를 엽니다.
2. Development Team과 Bundle Identifier를 확인합니다.
3. MobileSAM Core ML 모델과 `PrivacyInfo.xcprivacy`의 Target Membership을 확인합니다.
4. 실제 iPhone에서 카메라·마이크·사진 보관함 권한과 Archive를 검증합니다.

프로젝트 설정: iOS 16.0, Swift 5, Marketing Version 2.2, Current Project Version 19.

### Android

1. Android Studio에서 `Android/TopOut`을 엽니다.
2. Gradle JDK 17을 사용합니다.
3. Gradle Sync 후 모델 검증과 테스트·디버그 빌드를 실행합니다.

```bash
cd Android/TopOut
./gradlew downloadMoveNetPoseModel
./check_models.command
./gradlew testDebugUnitTest assembleDebug
```

첫 MoveNet 빌드는 공식 모델 다운로드를 위한 네트워크가 필요하고, 이후에는 검증된 Gradle 캐시를 사용할 수 있습니다. 기존 tfhub.dev 직접 링크가 404로 종료되어 같은 원본을 제공하는 Kaggle Models 아카이브에서 받으며, 내려받은 파일과 캐시는 고정 SHA-256으로 검증합니다.

## 알려진 플랫폼 차이

- iOS는 Vision이 반환한 여러 observation 중 Motion 격자와 직전 추적 위치에 가장 잘 맞는 한 명을 선택합니다.
- Android는 MoveNet SinglePose 한 명과 3-of-4 anatomical group gate를 사용합니다.
- iOS는 active crop 전체를 Vision 입력으로 사용하고, Android는 Motion/Pose ROI를 동적으로 갱신합니다.
- Core ML, Vision, LiteRT, ONNX Runtime의 처리 시간과 카메라 포맷 지원 범위는 기기별로 달라질 수 있습니다.

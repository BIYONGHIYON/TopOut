# TopOut 소개·개발 사례 페이지

외부 프레임워크와 외부 폰트 요청 없이 동작하는 정적 소개페이지입니다. `index.html`, `styles.css`, `script.js`, `assets/`를 함께 제공합니다.

## 구성

1. 첫 화면: “등반 시작부터 완등 순간까지” / “녹화 후 자동으로 감지된 결과 구간을 바로 확인하세요”, 홍보 릴스·기존 모션그래픽 선택 탭, 제작 범위
2. 앱 소개: 한국 볼더링 촬영·SNS 공유 문화, 원본 누적 문제, 촬영·검토·선택 저장 흐름
3. 개발 과정: 앨범 후처리 대신 직접 녹화, 초기 CV와 MobileSAM, Motion에서 Vision Pose로 전환, 최고점 기준, 프리뷰 끄기, Pose Recovery, Android 모델 선택과 렌즈 전환 UX
4. 출시 후 개선: SAM 매트 경계, 저메모리 시작·분석 대기 복구, 재촬영 버튼의 사용 관찰과 5초 이동으로 전환, 실제 갤러리 저장본 조회 / 직접 사용하며 추가한 확대·정밀 편집·자동 녹화·녹화 중 매트 경계 수정
5. 해외 언어 확장: v2.0부터 9개 언어, 자동·수동 선택, 긴 번역과 플랫폼 UI 대응
6. 설치·고객지원 링크, 온디바이스 처리, 현재 릴리스

초기 매트 탐지, 정지 프레임 전환 상태 머신과 드래그 속도에 따른 정밀 편집, 등반 탐지·Pose Recovery와 MobileSAM 매트 탐지 설명은 접기 없이 항상 표시합니다. 직접 쓰며 발견한 타임라인 확대·드래그 정밀 편집·60초 자동 녹화·녹화 중 매트 경계 수정은 01~04의 독립 카드로 구분하며, 모두 왼쪽 설명·오른쪽 시각 자료의 같은 양식을 사용합니다. 모바일에서는 설명 다음에 시각 자료를 세로로 배치하고, 네 주제의 설명은 항상 표시합니다. 나머지 상세 로직은 네이티브 `details`/`summary`로 읽을 수 있습니다. 모바일 목차는 Escape·바깥 클릭·링크 선택으로 닫히며 현재 절을 표시합니다. 자바스크립트가 없어도 본문·상세 로직·영상·링크는 사용할 수 있습니다.

## 콘텐츠 근거 (2026-10-30)

- 개발 과정 02번 하단은 Motion으로 Pose 탐지를 시작하고 관절의 최하점과 매트 경계로 시작·종료를 판단하는 개요만 설명합니다. 시작·종료 여유선, 경계 보간, 유실 복구와 편집 끝점의 세부 내용은 이후 항목에 둡니다.
- 초기 Motion 판정의 세부 순서는 사용자 회고를 반영했습니다. 시작은 매트 주변 움직임 → 매트 영역 움직임 소멸 → 벽 영역 움직임, 종료는 탑홀드 주변 움직임 → 매트 경계 주변 움직임으로 설명합니다. 현재 Pose 기반 로직과 구분한 초기 접근 기록입니다.
- 검정 녹화 화면을 보고 주변 클라이머들이 관심을 보이며 어떤 앱인지 물어봤다는 경험은 사용자가 추가로 제공한 실제 사용 회고입니다. 녹화 화면의 홍보 의도와 함께 본문에 반영했습니다.
- 개인 경험, 한국 촬영 문화, 아이디어 선택, 초크·삼각대 흔들림, 약 60%의 초기 체감, 30분·1시간 촬영 문제, 홍보 의도와 릴스 성과 맥락은 사용자가 이번 개편 요청에서 제공한 개발 회고입니다. 성과 수치나 정식 평가 정확도로 확대하지 않았습니다.
- 초기 매트 CV: `git show 00c581e:IOS/TopOut/TopOut/Code/MatDetector.swift`. Chroma 중심 상·하단 bin 비교, 바로 아래 블록 균일도, 국소 경계 정제, 두 점 직선 근사, 밝기 fallback을 확인했습니다.
- 모델 전환 이력: 루트 `DEVELOPMENT_HISTORY.md` 및 커밋 `a2cc442`, `9c0f3bd`, `36d06e7`, `71c0872`, `6e8c5a8`, `50fe7c0`, `4996844`. 모델별 정량 성능 순위는 제시하지 않습니다.
- 현재 iOS 탐지: `iOS/TopOut/TopOut/Code/MotionDetector.swift`, `Config.swift`. Android: `Android/TopOut/app/src/main/java/com/topout/cam/detection/PoseClimbAnalyzer.kt`와 현재 README. 얼굴 제외, x별 6%·4% 경계, 2fps·4fps, 최대 6초 복구와 플랫폼별 복귀 차이를 반영했습니다.
- 현재 SAM 경계: iOS `Code/MobileSAMMatDetector.swift` 및 루트 README. 과거 페이지의 폭 40% 설명을 **현재 상단 직선 지지 비율 60%**로 정정했습니다. 모델 정확도 60%와 다른 값입니다.
- Android 카메라: `camera/CameraEngine.kt`, `ui/components/LensZoomGestureController.kt`. 논리·물리 렌즈 분기, 핀치 중 정지 프레임 확대, 손을 뗄 때 재바인딩, 되돌리기 취소, STREAMING·줌 완료 확인, 전환·시도 ID와 이전 렌즈 복구를 확인했습니다.
- 정밀 편집: iOS `Code/TrimRangeSlider.swift`. 최대 30배, 0.1초, 정밀 진입 35pt/s·0.14초 / 이탈 55pt/s는 iOS 구현 수치임을 명시했습니다.
- 60초 자동 녹화: iOS `Code/HoldVC+MatLine.swift`, Android `TopOutViewModel.kt`. 매트 분석 완료부터 60초 뒤 현재 보정 경계선으로 기존 3초 카운트다운을 시작하고 마지막 5초에만 예고합니다. 탑홀드는 결과 화면에서 고르므로 대기 조건이 아니며, 수동 시작·재촬영·화면 이탈·앱 비활성화·카메라 중단 시 예약을 취소하고 보정 화면이 다시 준비되면 새로 기다립니다. v3.0에서 제거됐다는 문구를 삭제하고 현재 동작으로 복구했습니다.
- 저장 검증·재촬영·타임아웃·언어: 현재 루트 및 플랫폼 README, v1.5~v3.0 노트. 댓글은 사용자 정정에 따라 **Android 출시 소식이 아닌 홍보 릴스**로 표기했습니다.
- 현재 릴리스: iOS `project.pbxproj`의 3.0 / 23, Android `app/build.gradle.kts`의 3.0 / 23 / minSdk 26과 대조했습니다.

## 로컬 미리보기

저장소 루트에서 다음 명령을 실행한 뒤 `http://127.0.0.1:8765`를 엽니다.

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory portfolio
```

정적 페이지 변경만 포함하며 앱 기능·버전·권한·데이터 처리 정책은 변경하지 않습니다. 공개 저장소 README 및 고객지원·개인정보 문서와 대조했으며 이번 개편에 따른 정책 변경은 없습니다. 새 앱 릴리스가 아니므로 플랫폼 빌드 노트나 앱 빌드를 생성하지 않습니다. 공개 배포와 Git 커밋·푸시는 별도 작업입니다.

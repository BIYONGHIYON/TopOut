# TopOut Android v3.0 (versionCode 23)

## 릴리스 기준

- Version name: `3.0`
- Google Play versionCode: `23`
- Minimum SDK `26`, Compile / Target SDK `36` 유지

## 주요 변경 사항

### 녹화 시작과 매트 경계

- 녹화 시작 버튼을 녹화 정지 버튼과 같은 빨간 캡슐의 아이콘 전용 버튼으로 바꿈(흰 원 + 빨간 원, TalkBack `녹화 시작`)
- 자동 구간 탐지를 켜면 `준비 완료` → 매트 경계 측정 → 보정 화면(`다시 촬영` · 빨간 녹화 시작, 시스템 뒤로가기 = 다시 촬영) 순서. 끄면 미리보기 화면의 빨간 녹화 시작 버튼으로 바로 녹화
- 녹화 전에는 탑홀드를 고르지 않음. 보정 화면(`CameraStage.SELECT`)은 매트 경계만 다룸
- 준비 완료 후 매트 분석이 끝나 보정 가능한 상태부터 60초 뒤 현재 경계선으로 기존 3초 녹화 카운트다운을 시작하는 기능 복구. 마지막 5초에만 자동 시작 예고. 수동 시작·재촬영·화면 이탈·앱 일시정지·카메라 재연결 시 예약 취소, 보정 화면 복귀 후 새로 60초 대기. 자동 구간 탐지를 끄면 자동 시작하지 않으며, 탑홀드는 결과 화면에서 고르므로 대기 조건에서 제외
- 실시간 영상이 보이는 녹화 중에는 파란 점으로 경계선을 보정할 수 있고, 손을 떼면 진행 중인 탐지 상태를 유지한 채 바로 반영(`PoseClimbAnalyzer.updateMatLine`)
- 녹화 중 완등 판정은 항상 가장 높이 올라간 관절을 기준으로 함

### 탑홀드는 결과 화면에서 지정

- 영상을 멈추고 탑홀드를 탭하면 `MediaMetadataRetriever.OPTION_CLOSEST`로 그 시각의 프레임을 뽑아 MobileSAM 마스크를 만들고 `탑홀드 마스크`를 켬. 다시 탭하면 새로 만듦
- 두 손가락으로 영상과 마스크를 최대 5배까지 확대·이동한 뒤 탭할 수 있음. 확대가 화면에 반영되도록 탑홀드 마스킹을 켠 녹화의 결과 플레이어만 `TextureView` 방식(`res/layout/review_zoomable_player_view.xml`) 사용
- `탑홀드 마스크` 버튼은 탑홀드 마스킹을 켠 녹화에만 표시. 마스크를 고르기 전 누르거나 처음 영상을 멈추면 탭 안내, 마스크가 체크된 상태에서는 확대해 다시 고를 수 있다는 안내 표시(도움말을 켰을 때)
- 마스크를 바꾸면 이전에 마스크를 넣어 저장한 결과는 지금 선택과 다른 것으로 봄. 분석 중에는 마스크·저장 버튼만 잠그고, 분석이 예외로 끝나도 버튼이 잠긴 채 남지 않음
- 결과 화면 프레임은 Android 8.1 이상에서 `getScaledFrameAtTime`으로 처음부터 줄인 크기로 뽑음
- 설정의 탑홀드 마스킹 설명을 `결과 화면에서 탑홀드를 탭해 영상에 표시`로 바꿈

### 탑홀드 외곽선 로직 교체

- 기존: 두 번째 마스크만 쓰고 탭 지점 색과 다른 픽셀을 HSV로 지운 뒤 가장 큰 덩어리를 볼록 껍질로 그림. 실패하면 주변 8점을 다시 디코딩. 흰·회색·두 색 홀드와 볼륨을 일부만 잡는 문제
- 새 로직(`sam/HoldOutlineExtractor.kt`, iOS와 같은 규칙):
  - 탭 한 점의 다중 마스크 3개와 `iou_predictions`를 함께 받아 모든 후보를 보고, 저해상도 logit을 긴 변 512칸 격자로 이중선형 확대
  - 탭한 칸과 이어진 영역만 남기고 안쪽 구멍을 메움. 색상으로 자르지 않음
  - 화면의 25% 이상 펼쳐지거나 3.5% 이상을 덮는 후보는 벽·매트로 보고 제외
  - IoU + 0.5 × 안정도로 고르되, 점수 차이 0.03 이내에서 1.6배 이상 작은 후보가 있으면 탭한 홀드 하나만 잡도록 그쪽을 씀
  - 열림 2칸으로 잔가지 제거, 선 굵기 절반만큼 바깥으로 키운 뒤 닫힘 3칸으로 홈을 메워 테두리가 홀드를 가리지 않게 함
  - Douglas–Peucker(1칸)와 Chaikin 3회로 윤곽선을 다듬음
- 최소 원 지름을 절반으로 줄임: 짧은 변의 3.75%, 22px 이상, 6% 이하. 이보다 작은 홀드는 홀드 가운데에 최소 원, 홀드를 못 찾거나 5초를 넘기면 탭 위치에 최소 원
- 같은 모델 출력에서 iOS와 Android 외곽선이 0.0002px 이내로 일치함을 확인
- 색상 필터·주변 재탐색·볼록 껍질 코드와 관련 설정값 삭제

### 자세 인식 가짜 뼈대 거르기

- MoveNet이 사람이 없는 벽에서 홀드 위에 손가락 크기의 뼈대를 만들고 사람으로 판정하는 문제를 막으려고, 믿을 만한 관절이 선택 영상 긴 변의 5%보다 좁게 몰리면 사람으로 보지 않음(`PoseHumanGate.hasPlausibleSize`)
- 고정 촬영 영상 22개(약 1,700프레임)를 Apple Vision·MoveNet·RTMPose·MediaPipe로 비교: 실제 등반자의 최소 관절 폭 5.6%, 이 기준으로 가짜 뼈대 41건 중 20건 제거, 실제 사람 손실 0건

### 결과 화면

- `다시 촬영` 버튼 제거. 1행 `5초 전 · 재생/정지 · 5초 후 · 선택 구간 저장`, 2행 `탑홀드 마스크 · 닫기`. 탑홀드 마스킹을 끈 녹화는 `닫기`가 2행 전체를 씀

### 메모리

- MobileSAM ONNX 세션은 녹화를 시작할 때 닫고, 녹화가 끝나면 탑홀드 마스킹이 켜져 있을 때만 결과 화면용으로 다시 엶. 카메라 화면에서는 자동 구간 탐지를 쓸 때만 `준비 완료`용으로 미리 엶
- 메모리 부족 알림(`onTrimMemory` RUNNING_LOW 이상, 화면 숨김 포함)에서 분석 중이 아니면 세션을 닫고 다음 분석 때 다시 엶
- ONNX Runtime CPU arena를 꺼 인코더 추론 뒤 가장 컸던 작업 메모리를 계속 붙잡지 않음

### 기타

- 9개 언어 문구 정리: 결과 화면 탑홀드 탭 안내·마스크 지정·확대 안내 추가, 탑홀드 마스킹 설명 변경, 녹화 전 탑홀드 선택·탑홀드 추적·결과 화면 다시 촬영 경고 문구 삭제. 자동 녹화 직전 예고는 9개 언어로 복구
- v3.0 개발 중 자이로·중력 센서로 거치를 감지해 경계선을 자동으로 재는 방식을 시도했다가 기기 테스트 뒤 준비 완료 방식으로 되돌림. 기록: [AUTO_MAT_PIPELINE_DESIGN.md](../../AUTO_MAT_PIPELINE_DESIGN.md)

## 릴리스 전 확인

- 자동 구간 탐지 ON: `준비 완료` → 경계선 → `다시 촬영`/빨간 녹화 시작, 뒤로가기 = 다시 촬영. OFF: 빨간 녹화 시작으로 바로 녹화
- 분석 완료 55초 후 예고·60초 후 기존 3초 카운트다운, 현재 보정 경계선 사용, 수동 시작·재촬영·앱 일시정지 뒤 이전 예약 취소와 복귀 후 새 60초 대기 확인
- 보정 화면에서 핀치 줌·회전이 막히는지
- 실시간 영상을 켠 녹화 중 파란 점으로 고친 경계선이 이후 판정에 반영되는지
- 사람이 없는 벽을 오래 비춰도 등반 시작이 잘못 잡히지 않는지
- 결과 화면에서 확대 → 탑홀드 탭 → 마스크가 홀드 가장자리 바깥에 그려지고 저장 영상에 반영되는지. 작은 홀드는 최소 원, 벽을 탭하면 최소 원
- 결과 화면 5초 전·5초 후·저장·탑홀드 마스크·닫기 동작
- 램 2–4GB 기기에서 4K 녹화와 결과 화면 첫 탑홀드 탭이 5초 안에 끝나는지
- Play Console 업로드 전 versionName `3.0`, versionCode `23`, 16KB page alignment 확인
